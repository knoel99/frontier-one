# AGENTS.md

Instructions for any coding agent working on this repository: the Frontier framework itself. (A mission's own
workspace gets its own AGENTS.md from the launcher.)

- The previous race framework was removed from the tree on 2026-11-14; it stays in git history (`git show 7223bd6:old/<path>`).
- Everything provider-specific goes in `config/providers.toml` (models, reasoning values, speed modes) and
  `config/prices.toml` (generated by `tools/update_prices.py`); everything harness-specific in
  `config/harnesses.toml` (launch) and `frontier/harnesses.py` (files). Code stays provider- and harness-neutral.
  Model ids and reasoning values come from the provider's `/models` endpoint and `python3 -m frontier ping`, never
  from memory.
- Generated files, never edited by hand: `catalog/*.json` (`tools/build_catalog.py`), `config/prices.toml`
  (`tools/update_prices.py`), and the harness files listed by `python3 -m frontier harnesses` (`CLAUDE.md`,
  `.mcp.json`, `.codex/`, `.agents/`, `.claude/`, `opencode.json`, … : `python3 tools/sync_harnesses.py`).
  Hand-written: `catalog/*-guide.md` (state the date and what was checked live), `roles/`, `prompts/`.
- A flow agents repeat belongs in `frontier/infra.py` as a ready-made function.
- The prompts (`prompts/`, `roles/`) state facts, requirements and evaluation, not strategy: the mission's AI
  decides how to work.
- The framework's tools are served to this repository's harness by the `frontier` MCP server
  (`python3 -m frontier.mcp`); the shell fallback is `bin/frontier call <tool> '<json>'`.
- Standard library only at run time (`huggingface_hub` only for publishing). Before committing:
  `python3 -m ruff check .`, `python3 -m pytest -q`, `python3 tools/sync_harnesses.py --check`.
- Write in English.

## Rules and what enforces them

Each rule is here because the same mistake was fixed at least twice. When a mistake comes back, fix it at the highest
level that works (structure, then a check whose message names the fix, then a test) and add its line; a rule that
nothing enforces is the last resort.

| Rule | Enforced by |
|---|---|
| A model call under a budget goes through `Budget.metered_chat` or `with budget.call(...)`; a call nobody settled is charged its worst case | `budget.Call`; `tests/test_rules.py` |
| A JSON file is written with `budget.write_json`; a JSON state file is changed with `budget.update_json`; a lock is taken with `budget.locked` | `tests/test_rules.py` |
| Every `subprocess.run` states `check`; with `check=False` the code reads the exit status | ruff `PLW1510` |
| An `except Exception` carries its reason on its line; a `noqa` suppresses a rule that is enabled | ruff `BLE`, `RUF100` |
| Parallel model calls never spend more than the cap together, in any order of their steps (`budget.py`: `call`, `Call`, `reserve`, `release`, `_fits`) | `tests/test_call_orders.py` runs every order on the real code; `python3 tools/check_model.py` checks the TLA+ model (`formal/README.md`) |
| Under a cloud budget, the raw-call lists of `frontier/tools.py` name what is free; the rest is refused | the guard itself; `test_raw_cloud_calls_the_framework_does_not_know_are_refused_under_a_budget` |
| Every harness install names its version; a recipe or a version changes only with that harness's live mission in the same change (`python3 tools/verify_live.py --root DIR --harness <name>`), and the changed line states the version and the date | the pin: `test_every_harness_install_is_pinned`; the live mission: nothing, since it needs the vendor's CLI, a key and a paid session |
